# Security reporting

Do not include secrets, customer documents or exploit details in public issues.
This repository is public. Use an existing private founder contact if you have one.
A dedicated reporting address is not yet published; private vulnerability reporting
was verified disabled on 2026-10-14. Do not post vulnerability details or personal
information in public issues. If no private channel is available, request a private
contact without disclosing the vulnerability. The founder must establish a public
reporting route; no reporting feature is claimed enabled.

Include the affected revision, synthetic reproduction, expected boundary and
observed impact. Do not test against production or other people's accounts.
The founder triages containment and disclosure with the engineering owner.
See [threat model](docs/security/threat-model.md) and
[incident procedure](docs/engineering/release.md).

There is no released version or production security verification yet.
